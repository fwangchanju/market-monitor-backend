# 작업 진행 프로세스

- git commit, git push, 파일 수정(Edit/Write) 등 실제 변경을 실행하기 전에 먼저 무엇을, 어떻게 할지 설명하고 사용자의 의견을 구한다.
- 사용자가 다시 검토/질문하면 그에 답하고, 결정된 방향으로 사용자가 명시적으로 작업 진행을 지시하기 전까지는 어떠한 경우라도 직접 판단해서 진행하지 않는다.
- PR 병합(merge)은 어떤 경우에도 직접 수행하지 않는다.
- commit/push를 지시받으면, 현재 브랜치에 열려 있는 PR이 있는지 먼저 확인한다. 있다면 그 사실을 알리고, 기존 PR에 이어붙일지 여부를 사용자에게 확인한 뒤 진행한다.
- 열려 있는 PR이 없다면 commit.md의 브랜치 명명 규칙에 따라 main 브랜치 기준으로 새 브랜치를 생성 후 PR을 연다.

## 단계별로 나누어 진행하는 대규모 기능 작업

- 그날 작업하기로 한 내용 중 가장 대표적인(혹은 분량이 가장 많은) 주제를 기준으로 브랜치명을 정한다. 프론트/백엔드는 각자 독립적으로 브랜치명을 정하며 서로 맞출 필요는 없다. 해당 브랜치로 그날 작업한 커밋 전체를 하나의 PR로 main에 병합한다. 각 단계는 하나의 커밋으로 남긴다.
- 각 단계를 시작하기 전에, 해당 단계의 세부 작업 목록과 세부 작업별 간략한 진행 계획을 먼저 제시하고 사용자의 확인을 받는다.
- 세부 작업은 한 번에 하나씩만 진행한다. 하나를 완료하면 사용자의 확인("오케이" 등)을 받은 뒤에 다음 세부 작업으로 넘어간다.
- 한 단계의 모든 세부 작업이 끝나면, 커밋 전에 다시 사용자의 확인을 받는다. 확인 후 그 단계 전체를 하나의 커밋으로 묶는다.
- 커밋 후에는 곧바로 다음 단계의 세부 작업 목록 및 계획을 제시하고, 위 과정을 반복한다.
