# 글쓰기 규칙

이 프로젝트의 글은 사람이 아니라 모델이 쓴다. 코드는 리뷰로 걸러지지만 글은 그렇지 않아서,
읽는 사람이 "AI가 썼구나"를 먼저 느끼게 된다. 그걸 줄이려는 규칙이다.

판정에 쓰는 룰북은 `.claude/agents/humanize-references/quick-rules.md`에 있다.
그건 일반적인 한국어 산문 기준이고, 이 문서는 여기서 지킬 것만 추린 것이다.
둘이 어긋나면 이 문서를 따른다.

## 적용 대상

세 군데다.

- PR 설명과 PR 코멘트
- 커밋 메시지 (형식은 `commit.md`, 문체는 이 문서)
- `docs/**` 중 2026-09-07 이후에 쓴 문서와 `CLAUDE.md`

사용자와의 대화는 대상이 아니다. 코드 주석과 로그 문구도 아니다.
`docs/rules/commit.md`도 대상이다. `docs/rules/style.md`는 마지막 단계에서 내용까지 재작성할
예정이라 그때 함께 본다.

## 문체

문서는 평서체(`~한다`)로, PR 설명과 코멘트는 존댓말로 쓴다. 한 글 안에서 섞지 않는다.

## 하지 말 것

**볼드를 결론마다 붙이지 않는다.** 문단에 하나면 충분하고, 없어도 된다.
세 줄에 한 번씩 나오면 그건 강조가 아니라 배경이다.

**대시(—)로 부가 설명을 달지 않는다.** 쉼표나 괄호를 쓰거나 문장을 나눈다.
원문에 이미 있던 대시는 그대로 둔다.

**연결어미 뒤에 쉼표를 찍지 않는다.** `~하고, ~하며, ~지만,` 처럼 이어붙이면
문장이 늘어지고 리듬이 균일해진다. 이 프로젝트 문서에서 가장 크게 벗어났던 항목이다.

**대구를 반복하지 않는다.** `A가 아니라 B다`, `~하는 게 목적이지 ~가 목적이 아니다`
같은 구문은 한 문서에 한 번이면 족하다.

**이모지를 쓰지 않는다.** 체크마크와 경고 표시도 포함한다. 상태를 나타내야 하면 글로 쓴다.

**결산 표현을 남발하지 않는다.** `정리하면`, `결론적으로`, `즉`, `따라서`로
문단을 닫는 습관을 줄인다. 문서당 한두 번이면 충분하다.

**과장 부사를 빼고 사실을 쓴다.** `정확히`, `핵심은`, `결정적으로`, `치명적인`은
대부분 없어도 뜻이 통한다. 없으면 뜻이 달라지는 자리에만 남긴다.

**`~하는 이유다`로 문장을 끝내지 않는다.** 도치 결산이다. `그래서 ~다`로 쓴다.

## 형식

**표는 셋 이상을 같은 기준으로 비교할 때만 쓴다.** 두 항목이거나 비교가 아니면 산문으로 쓴다.

**절 제목을 정형화하지 않는다.** `## 무엇을`, `## 왜`, `## 검증`이 매번 같은 순서로
나오면 템플릿을 채운 티가 난다. 그 글에 필요한 제목을 그때 정한다.

**불릿을 세 블록 이상 잇지 않는다.** 나열이 의미 있는 자리만 남기고 나머지는 문단으로 푼다.

## 지키지 않아도 되는 것

사실과 수치가 먼저다. 문체를 다듬느라 근거가 흐려지면 규칙을 어긴 것보다 나쁘다.
경고 문구처럼 눈에 띄어야 하는 자리는 볼드를 써도 된다.

이미 올라간 PR 코멘트와 커밋 메시지는 고치지 않는다. 앞으로 쓰는 것부터 적용한다.
